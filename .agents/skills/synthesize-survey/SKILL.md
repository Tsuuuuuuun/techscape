# synthesize-survey

## 共通の入口
対象 vault のルートを特定し、そこの AGENTS.md と対象ノートを読む。ルート不明なら現在の作業場所から確認し、別 vault を推測で更新しない。テンプレートは vault 内の 90 Templates を使う。インストールされたこの SKILL.md からの相対位置を vault と見なさない。分類・References・停止規則の正本は AGENTS.md。ユーザーの明示した依頼を優先する。

## 手順
1. 中心の問い、想定読者、対象範囲を依頼とノートから定める。関連する Issue / Concept / Technology を読み、各ノートの更新時点と根拠の確かさを確認する。
2. 「問題 → 必要な概念 → アプローチの比較 → 統合した主張 → 限界」の論旨を組む。複数ノートの要約を並べるだけにしない。比較軸と、結論を左右する不足を先に明らかにする。
3. 必須の不足だけを現在の問いに必要な深さで確認する。大きな追加調査が必要ならその点をギャップとして残し、証拠以上の結論を書かない。
4. `90 Templates/survey.typ` を基に `40 Surveys/<slug>/main.typ` を作成・更新する。既存 Survey があれば再利用する。外部パッケージをむやみに増やさず、資料の要約、比較からの推論、自分の仮説を区別する。
5. Notes used に実在する vault 相対パス、末尾の References に原資料を記載する。重要な主張は参照番号で根拠に結び付ける。複数ノートの References を統合するときは同じ資料の重複を除き、Survey 内で参照番号を割り当て直す。異なる版・該当箇所の情報を失わず、本文の全参照番号が意図した資料に対応することを確認する。Notes used のパスは Typst の `#raw("パス")` で記載し、外部資料へのリンクは `#link("URL")[表示名]` で記述する。
6. 実行環境に Typst があればコンパイルして構文・参照・フォント警告を確認する。PDF を提供する場合はレンダリングして文字欠け、表のはみ出し、改ページも目視確認する。実行できなければソースを提供し、未検証箇所を明示する。

## 知識の還元と終了
統合で見つかった既存ノートの誤りや不足は、更新を含む依頼の範囲で反映する。新たな概念が出たというだけでノートを増やさない。ギャップと後続調査の問いは Survey の Knowledge gaps にまとめる。

中心の問いへの回答と限界が説明できれば終了する。成果物の場所、主な結論、知識ギャップ、元ノートの変更、コンパイル・表示確認の結果を伝える。
